# 架构、数据结构与权限边界

## 当前入口

居民/家属网页 `/app`、社区工作台 `/console` 与帮助页 `/help` 由同一 FastAPI 服务提供；`miniapp/` 保留为历史源码。网页通过 JWT 调用 `/api`，服务端以 SQLAlchemy 访问开发 SQLite；正式环境设计使用 PostgreSQL，但尚未在 PostgreSQL 演练。应用启动时开发环境可 `create_all`，生产环境必须先用 Alembic 迁移，不能把初始迁移用于旧 v0.1 原表直接升级。

```text
居民/家属网页 ─┐
社区工作台 ────┼── HTTPS（正式环境）── FastAPI：鉴权、对象权限、审计 ── SQLAlchemy ── 数据库
帮助页 ────────┘                         │
                              受限助手工具/报告证据选择 ── DeepSeek API
```

## 核心数据

- `users`：角色、所属社区、登录与锁定状态、邀请码、会话版本，以及已启用和待确认的 TOTP 状态；密码为哈希，TOTP 密钥在配置字段密钥后加密。`residents` 独立于账号，使员工可先登记没有线上归属的档案；居民/认领电话同样可加密。
- `claim_requests`：已有档案认领申请。档案号/姓名/电话匹配仅建立待核验记录，不直接设置 `owner_user_id`；不匹配仍返回统一提示。员工线下核验后才能批准。
- `consent_events`：社区护理目的的追加式同意/撤回。最新事件决定是否可访问；纸质同意必须由非提交人的同社区员工复核通过，待复核和驳回不能授予访问。
- `family_grants`：本人以家属的邀请码指定共享字段和期限；到期、本人撤回或家属拒绝后失效。
- `vitals`、`questionnaires`、`questionnaire_responses`、`reminders`、`visits`：手工测量、非临床问卷与本人答案、端内待办、线下随访；没有诊断评分或自动推送。`audit_logs` 只存动作、账号、对象 ID 和时间，不存健康正文。
- `medical_reports`：报告所属居民、上传者、不可变 SHA-256、私有存储键、页数、任务状态/租约、候选转录和确认结果。候选与人工确认文本是独立列，在配置字段密钥后加密；原始文件在 `REPORT_STORAGE_DIR` 下以服务端随机键存储，配置 `FIELD_ENCRYPTION_KEY` 后用 AES-GCM 加密。`report_vital_links` 记录明确导入的条目与健康指标，删除指标后保留条目来源记录。

## 权限与统计

| 操作 | 本人 | 已获授权家属 | 同社区且同意已生效的员工 | 管理员 |
|---|---|---|---|---|
| 读基本档案/测量 | 自己 | 仅获授权字段 | 可 | 不可读个人明细 |
| 记录测量/待办 | 自己 | 不可 | 按业务范围可 | 不可 |
| 读问卷原始答案 | 自己 | 不可 | 不可 | 不可 |
| 授予/撤回家属访问和社区同意 | 自己 | 仅可拒绝家属授权 | 不可替本人操作 | 不可 |
| 复核纸质同意和认领 | 不可 | 不可 | 同社区且非本人提交者复核同意 | 不可 |
| 上传/读取报告原件及草稿 | 自己 | 不可，即使获测量授权 | 同社区且护理同意有效 | 不可 |
| 社区健康统计 | 不可 | 不可 | 仅本社区有效同意范围 | 全局聚合接口 |

服务端 `app/deps.py` 执行对象级检查，`app/reporting.py` 提供最新有效同意过滤，网页隐藏按钮不是授权依据。`/api/community/health-stats` 先计算有权访问范围的聚合，再独立处理搜索及列表分页，避免页数改变总量。切换账号和退出时网页清理旧 DOM 与会话数据。

## 助手边界

`/api/assistant/chat` 需要登录。服务端向 DeepSeek 发送用户输入的消息、历史对话和帮助知识；默认只提供帮助搜索。用户明确勾选后，才加入当前角色专用的只读工具：居民本人待办数量/最近日期、家属有效授权数、员工本社区有效同意居民/随访数、管理员社区/有效同意居民数。工具不接受任意用户、居民或社区 ID，不返回姓名、电话、提醒标题、原始测量或问卷答案，也不能写入业务。上游地址仅允许 `api.deepseek.com`，非生产模式另允许开发回环地址；凭据只在服务端环境读取。

## 报告导入与审核

上传是二进制原始请求体，限制 PDF、PNG、JPEG、WebP、10 MiB、5 页。解析在受限子进程中进行，存储路径由服务端 UUID 决定；原件 SHA-256 在读取和处理前校验。上传本身不发送云端。用户针对**每份报告**明确勾选后，`POST /api/reports/{id}/extract` 才将任务排入数据库；worker 可内嵌运行，也可用 `python -m app.report_worker` 独立运行。任务有 7 分钟租约，处理中断不自动再次发送，须用户主动重试，最多 3 次。

worker 在每页发送前重查申请账号、会话版本、当前社区同意和任务租约。无图片且有足够原生文字的 PDF 发送文字；其他页发送图像，**页面可能包含姓名与完整检验内容**；仅连接受信任的 DeepSeek 地址，不抓取上传内容中的外链。模型生成逐页文字和项目候选；quote 对齐只是文字核查，图像页的文字与 quote 都由模型转录，**没有已校准置信度或 OCR 边框/坐标证明**。草稿不自动写入 `vitals`。用户对照原件确认报告归属、修正字段后，可不导入任何健康指标；如明确选择导入，服务端只接受确切名称/单位/值匹配的血压、血糖、体重及有效带时区的实际测量时间，其他检验项保留在已确认报告中。确认后的版本不可随意重写。

## 已确认报告问答

`POST /api/assistant/report-chat` 只接受一份身份已确认的报告，须由本人或当前有效护理同意下的同社区员工访问，且请求明确设 `allow_report_data:true`。服务端将人工确认字段和用户问题/历史发给 DeepSeek；原始 PDF/图片、其他报告与未审核草稿不进入这次模型上下文。模型只返回白名单意图与证据 ID 的 JSON，`app/report_answers.py` 以人工确认值构造事实文字，并从不可变候选中取得对应的原文片段与页码作来源卡；模型不能自行产生引用 ID、quote 或 page。图片页片段来自模型转录，并非原件像素坐标证明。无法定位时标记证据不足，医学请求只给边界提示。摘要若选择少于报告总项目数，显示已列数和总数。

调用模型前后均重新核验账号/会话、同意、报告状态与版本、候选及已确认文本哈希和原件 SHA-256；前端在切换报告、版本或账号时清空许可与历史并取消在途请求。后端每账号限 6 次/分钟，上下文最多 100 项、40000 字符，响应最多 8 个来源。问答不改动报告或测量，审计只记录读取动作而不保存问答文本；无新增数据库迁移。

## 运维约束

认证支持密码强度、登录限流/锁定、`token_version` 会话失效、分阶段 TOTP。进程内限流不适合多实例；CSP 因单文件网页内联脚本仍允许 `unsafe-inline`。正式运行还需 HTTPS、私有报告存储备份/删除与密钥轮换、PostgreSQL 迁移和恢复演练、机构审批流程、渗透测试及合规评审。详见 `DEPLOYMENT.md` 和 `SECURITY_PRIVACY.md`。

管理员可在工作台“安全与设置”按社区开通第二位员工，并查看、停用或启用账号，以满足纸质同意的非提交人复核要求。网页不提供管理员创建、角色编辑或密码重置。

报告问答仅对连接失败或空/畸形/不完整结构最多重试一次；每次发送前刷新账号、会话、报告授权、内容哈希和原件SHA。单次网络超时最多18秒，总选择预算37秒、路由40秒；HTTP失败和伪造引用不重试，也不输出无来源回答。
