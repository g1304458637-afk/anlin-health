## v0.5 报告识别实测

- 用户明确允许将生成的虚构文件发送 DeepSeek；测试仅使用 `assets/report-samples/` 的虚构 PDF 与 PNG，没有真实居民报告。
- 按原件 SHA-256 保留私有副本。上传不触发云端调用；逐份勾选允许后才入持久队列。原件/预览/候选仅本人或当前有效同意的本社区员工可访问，家属测量授权和管理员身份不包含报告。
- 真实 DeepSeek：两页可选中文文本 PDF 提取 11 项，扫描 PNG 提取 6 项。两次独立直连接口验证及本地 API→数据库队列→模型路径均成功。实际 API 返回候选的姓名、采样时间、报告时间与样本一致；项目名、结果、单位、参考范围和标记逐项匹配标准答案，没有项目差异。
- 标题候选使用了通用“检验报告”；浏览器对照原件更正为“检验记录功能测试单”。这说明结构化 JSON 与项目比对通过不代表全部字段无需人工核对。
- 原文 PDF 优先提取文本；含栅格图或没有可靠文本层的页面使用视觉模型。图像模式的文字及 quote 均是模型转录，不是经过独立 OCR 校验的坐标证据，不输出校准置信度。
- 真实浏览器完成 PNG 文件选择、上传、云端许可、自动状态更新、姓名不一致提醒、逐字段编辑、明确实际测量时间、确认报告。确认后新增血压 132/84 mmHg、血糖 5.8 mmol/L、体重 62.5 kg，历史页面分别显示 2026-10-20 08:30 本地测量时间。其他三个检验项目只保留在报告内。
- 浏览器打开两页 PDF 草稿并切换第二页，验证页码来源和原件放大/适应宽度控件。报告窗口关闭、退出及账号切换清理由前端回归覆盖。
- 对同一已确认报告再次提交相同复核体，返回原来的三个 Vital ID，没有重复入档。更改复核体、旧版本、重复 item、单位/数值不符被拒绝；已导入指标删除后保留导入痕迹，不会重放生成。
- 原件、候选和人工值分开保存。正式配置加密密钥时，原件 AES-GCM、数据库候选/人工值加密。测试验证密文没有原文、密文篡改不返回文件、原件 SHA 篡改拒绝。
- 队列验证覆盖：失效会话、员工同意撤回（含两页之间撤回）、过期租约不自动重发、旧租约不能覆盖新状态、服务失败保留原件。文件解析在受限子进程中执行，限制文件/像素/页数/CPU/墙钟时间；Linux 另外设置地址空间上限，macOS 不宣称同等内存限额。
- 实测比对证据：`assets/report-samples/live-verification.json`；截图：`assets/v0.5-report-confirmed.png`。这只是合成功能验证，不是医院样本准确率、临床有效性或真实人员人工验收。

## v0.6 已确认报告问答实测

- 报告确认后，顶部“询问这份报告”进入同一个助手的报告模式。每次绑定一份已确认报告；页面显示文件名和版本。问答另有默认未勾选的许可，不继承识别许可或普通待办查询许可。
- 模型接收当前报告的确认字段、问题及用户同意的本次历史。原始 PDF/图像、原文转录、未确认草稿和其他报告不在这次服务端数据载荷内；用户主动输入的文本仍可能包含自行填写的信息。模型只选白名单证据 ID 和意图；服务端从人工值生成答案，并从不可变候选绑定引用与页码。
- 所有引用核验项目 ID、页码及原文锚点；人工修订字段显示中文标签，同时保留确认值与原文转录。图片的“原文”明确称模型转录，不声称经过独立 OCR 或像素坐标验证。元数据只有能在报告页内定位时才作为来源。
- 回答前后核对当前账号、会话版本、员工同意、报告确认状态/版本、确认和候选文本哈希、原件 SHA-256。测试曾发现 `expire_on_commit=False` 下回滚不足以刷新身份缓存，已显式失效 ORM 缓存；并发撤回同意、全端登出或报告数据变化时不会返回旧答案。
- 本轮把既有虚构双页 PDF 在浏览器核对标题后确认为报告，未再次导入测量，避免与上一轮 PNG 记录重复。其 11 项检验项目与既有 golden 一致。
- 真实浏览器在独立虚构数据库中，未勾选问答许可时提示先允许；勾选后实际向 DeepSeek 提问“这份报告的肌酐是多少？原文在哪一页？”，返回第 2 页已确认肌酐 77 μmol/L、参考范围 44-97、标记 N。来源卡显示相同原文；点击“查看原件页”打开同一份已确认 PDF 的第 2 页。
- 最终真实 API/DeepSeek 抽检四例：血糖 5.8 mmol/L 及参考范围/标记定位第 1 页；人工更正的报告名称定位标题原文；血钾未记录时返回 `insufficient_evidence` 且无来源；要求判断正常与服药时仅展示证据并返回 `medical_guidance_limited`。最初事实查询被模型过度归为医疗问题，已细化意图说明，最终数值查询返回 `supported`。
- 自动化覆盖：草稿/无许可不发送、家属即使有测量授权仍拒绝、跨社区拒绝、假历史不能制造数值、伪造/重复引用拒绝、页码/原文失配和原件篡改拒绝、参考值只逐字展示、多人授权变化、问答版本切换与过期回答丢弃。前端来源跳转再次 GET 校验报告、居民、确认状态和版本，并测试实际第 2 页加载。
- 最后一轮浏览器曾遇到一次统一的上游失败提示；相同问题独立请求返回 HTTP 200 / stop / lookup / p2-i1，未能稳定重现，确切原因未确认。已加入最多一次受限重试，只针对连接错误或空/畸形/不完整选择；每次发送前重新核对授权和原件。单次网络等待不超过18秒、选择阶段总预算37秒、路由总时限40秒；HTTP错误和无效引用仍直接失败。模拟测试验证空结果后成功、重复失败、连接后恢复，以及重试前登出/撤回阻止第二次发送。最终版本上四类真实 API/DeepSeek 问答再次通过，浏览器相同肌酐问题成功返回第2页原文；未据此承诺上游永不失败。
- 问答不修改健康记录，不保存问题或答案；仅审计动作/账号/报告 ID。每账号 6 次/分钟，最多 100 项和 40000 字符的确认字段上下文，一次最多 8 个来源；概览只覆盖部分项目时明确列出数量。没有跨报告比较、临床诊断或用药建议。
